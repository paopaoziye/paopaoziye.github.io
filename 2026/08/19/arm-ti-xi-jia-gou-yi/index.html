处理器架构

Arm体系架构

Arm体系架构（一）

1.引言

①简介

概述：Arm是一种以精简指令集RISC理念为基础的处理器架构家族，兼顾了优秀的执行效率、能效表现和可扩展性

Arm体系架构是一套处理器的行为规范，规定指令集、寄存器模型、内存访问机制、异常与中断处理和特权级划分等内容

Arm体系架构一般不规定流水线级数、缓存大小和主频等具体硬件实现细节，通常由芯片设计厂商自行实现

Arm主要提供A、R和M三类架构Profile，分别面向应用处理器、实时处理器和微控制器等不同应用场景

每类Profile又包含Armv7、Armv8、Armv9等不同架构版本，更早还有Armv1-Armv6等架构，但是没有分类体系

不同Arm架构版本会在指令集、位宽、内存管理、安全机制和扩展功能等方面不断演进，例如Armv8-A引入了AArch64执行状态

Cortex-A、Cortex-R和Cortex-M是Arm公司基于相应架构Profile设计的处理器核系列，可以理解为Arm架构规范的具体实现

比如Cortex-M33基于Armv8-M架构，Cortex-A53和Cortex-A72基于Armv8-A架构，而Cortex-R52则基于Armv8-R架构

芯片厂商可以在这些处理器核上集成存储器、总线、外设及其他功能模块，设计成完整的MCU、SoC或其他类型的处理器芯片

②执行状态

概述：Arm定义了AArch32和AArch64两种执行状态，支持哪种状态取决于架构Profile、架构版本和处理器具体实现

AArch32与AArch64的主要区别体现在寄存器位宽与数量、所使用的指令集、地址空间以及异常与特权模型等方面

AArch32可使用A32或T32指令集，而AArch64使用重新设计的A64指令集

AArch32提供R0~R15等32位通用寄存器，而AArch64提供X0~X30共 31个64位通用寄存器，寄存器资源更加丰富

AArch32采用传统的User、SVC、IRQ、FIQ等处理器模式，而AArch64采用EL0~EL3异常级模型管理不同的特权级

AArch32主要采用32位地址模型，而AArch64支持更大的虚拟地址空间和物理地址空间，更适合现代操作系统

在同时支持AArch32和AArch64的处理器中，通常可以在异常进入或异常返回过程中结合目标异常级的配置完成两种状态的转换
M-Profile不采用AArch32/AArch64的执行状态划分，而是采用面向微控制器的32位程序员模型，并仅执行T32指令集
两种执行状态在系统寄存器、异常机制和SIMD模型等方面也存在差异，因此AArch64并非只是AArch32的简单64位扩展

③指令集

概述：Arm体系架构主要包括A32、T32和A64三种指令集，用于规定处理器可执行的指令及其编码格式和基本行为

A32和A64都采用固定32位指令编码，而T32由Thumb指令集发展而来，引入Thumb-2形成了混合使用16位和32位编码的指令体系

Thumb指令集以16位编码为主，目的是提高代码密度，Thumb-2在其基础上加入大量32位编码指令完善其功能

此外，A32、T32和A64在寄存器使用、寻址方式、条件执行方式、分支控制和扩展支持等方面均存在差异

A32指令规整且兼容性好，T32在兼顾功能的同时具有较高的代码密度，而A64寄存器资源丰富、地址空间大且64位运算能力强
A32和T32可以在同一个AArch32程序中协同使用，但需要通过特定的分支指令在两种指令集状态之间切换
A64不能与A32或T32指令直接混合执行，从AArch32代码迁移到AArch64时，通常需要针对A64重新编译或适配

2.寄存器模型

①AArch32寄存器模型

概述：在AArch32执行状态下，程序通常可见16个32位寄存器R0-R15，以及当前程序状态寄存器CPSR，如下所示

R0-R12为通用寄存器，R13、R14和R15则分别具有SP、LR和PC的专用含义，分别表示栈指针寄存器、链接寄存器和程序计数器

R0-R12主要用于数据运算、参数传递、临时数据保存和地址计算等，其具体用途还需要遵循AAPCS32调用约定

SP指向当前栈顶，栈通常用于保存函数局部变量、函数调用现场、中断现场和任务上下文等临时数据

LR通常保存函数调用或异常处理所需的返回信息，前者可通过BX LR等方式返回，后者则需要相应的异常返回机制恢复执行

PC用于保存和控制处理器的指令执行位置，分支跳转、函数调用、函数返回和部分加载指令可以更新PC以改变程序执行流

CPSR用于保存处理器的当前运行状态，包括条件标志位、当前执行状态、中断屏蔽状态和处理器模式等信息

部分异常模式拥有银行化寄存器，异常进入和返回过程中能够更快地保存、切换和恢复关键现场，减少软件手动保存寄存器的开销

银行化寄存器是指处理器切换到对应异常模式后，相同的寄存器编号会自动映射到另一组独立的物理寄存器

SPSR用于保存异常发生前的CPSR，因为异常发生时处理器需要改变CPSR，故将其保存到SPSR，直到异常返回再恢复

如果函数内部还需要调用其它函数，新的调用会更新LR中的返回地址，因此通常需要提前将原有LR保存到栈中，并在返回前恢复

②AArch64寄存器模型

概述：AArch64定义了31个64位通用寄存器X0-X30，同时提供栈指针SP、零寄存器XZR以及描述当前处理器状态的PSTATE

每个X0-X30都可以通过对应的W0-W30访问其低32位，向Wn写入数据时，对应Xn的高32位会自动清零

X29通常作为帧指针FP，用于建立和定位当前函数的栈帧结构，X30为链接寄存器LR，用于保存函数调用的返回地址

SP是独立的栈指针寄存器，不属于X0-X30通用寄存器组，只能在支持SP操作数的部分数据处理和访存指令中使用

XZR是特殊的零寄存器，读取时始终得到0，写入的数据则直接丢弃，可以避免为了读取常量0而额外分配一个真实寄存器

AArch64不再使用类似AArch32 CPSR的单一程序状态寄存器，而是使用一组程序状态字段，统称为PSTATE

AArch64中的程序计数器由处理器内部维护，主要通过分支、异常和PC相对寻址等机制使用，使指令编码和流水线行为更加规整

AArch64的不同异常级别提供对应的SPSR_ELx保存异常发生前的程序状态，并使用ELR_ELx保存异常返回地址

AArch64还提供32个128位SIMD&FP寄存器V0-V31，可按不同宽度访问，可用于浮点运算、向量运算、加密和媒体处理等

X29作为帧指针主要由AAPCS64和具体平台的调用约定决定，若允许省略帧指针，它也可以作为普通的被调用者保存寄存器使用
A64指令编码中的寄存器编码值31具有特殊含义，根据具体指令可能表示栈指针寄存器SP或零寄存器XZR

③M-profile寄存器模型

概述：M-Profile的寄存器模型类似于AArch32，但是针对MCU和实时控制场景简化了处理器状态、异常处理和栈管理机制

M-Profile保留R0-R15，并将程序状态拆分到xPSR中，并采用PRIMASK、BASEPRI、FAULTMASK和CONTROL完成中断和权限管理

xPSR是程序状态寄存器的组合视图，可分为APSR、IPSR和EPSR字段，分别用于记录运算状态、当前异常编号和指令执行状态

CONTROL主要控制Thread mode的特权级和栈指针选择，在支持浮点扩展的处理器中，还可包含浮点上下文状态相关控制信息

PRIMASK用于屏蔽所有可配置优先级的异常，提供一种简单的全局异常屏蔽机制，但不包括NMI和HardFault

BASEPRI用于设置一个优先级阈值，优先级数值大于或等于该阈值的可配置异常将被屏蔽，同样不能屏蔽NMI和HardFault

FAULTMASK用于进行最高级别的异常屏蔽，置位后可屏蔽除NMI外的所有异常，包括HardFault

M-Profile提供MSP和PSP两套栈指针，其中MSP常用于系统启动和异常处理，而PSP常用于应用线程或RTOS任务

在Thread mode下可以通过CONTROL.SPSEL选择使用MSP或PSP，进入Handler mode后则始终使用MSP

M-Profile的异常处理不依赖传统的银行化通用寄存器，进入异常时由硬件自动保存部分关键现场，并在异常返回时恢复
不同M-Profile架构版本和Cortex-M内核支持的特殊寄存器并不完全相同，比如Cortex-M0不提供BASEPRI和FAULTMASK

3.过程调用标准

①简介

概述：也称为PCS，是ABI的重要组成部分，用于规定调用者与被调用者之间的函数调用接口和行为约定

过程调用标准主要规定参数与返回值传递、寄存器保存责任、栈的使用与对齐以及函数调用过程等基本规则

Arm主要提供面向AArch32的AAPCS32和面向AArch64的AAPCS64，用于规范不同执行环境下的过程调用方式

ABI从更高层规定二进制程序之间的兼容接口，使不同编译器生成的目标文件、库文件和程序模块能够正确链接并协同运行

除过程调用标准外，ABI通常还涉及数据类型布局、目标文件格式、符号与链接规则以及异常展开等内容

高级语言编译器通常会根据目标架构、操作系统和编译选项，自动按照相应的PCS和ABI生成函数调用代码
汇编代码与编译器生成的代码交互时，同样需要遵循相应的PCS，并确保各程序模块采用兼容的ABI约定
AAPCS并不定义处理器的硬件异常进入和返回机制，但异常处理程序调用普通函数时，仍需要遵循相应的AAPCS

②AAPCS32

概述：规定AArch32的函数调用规则，采用满递减栈模型，即栈空间向低地址方向增长，SP始终指向当前栈顶位置

函数参数优先通过R0-R3传递，寄存器不足时则使用栈传递，对于需要两个连续寄存器的64位参数，采用R0-R1或R2-R3传递

对于返回值，不超过32位的数据通常通过R0返回，64位数据通常通过R0-R1返回，128位的容器化向量通常通过R0-R3返回

如果返回值为较大的结构体或复合数据类型，通常由调用者预先提供存储空间，并通过隐式参数传递地址，由被调用函数写入

AAPCS32规定调用者负责保存可能被覆盖的R0-R3、R12和LR，被调用者负责恢复需要保持不变的R4-R11和SP

调用者需要保存LR是因为函数调用指令BL和BLX会将返回地址写入LR，从而覆盖原有内容

被调用者保存R9的规则取决于具体平台ABI，当R9被定义为普通被调用者保存寄存器时，需要保证其值不变

R9在部分平台中具有特殊用途，例如保存静态基址或线程局部存储指针，除非明确目标平台约定，否则不应随意修改

静态基址用于保存访问静态数据区域的基准地址，程序可以通过它快速定位全局变量或静态变量

线程局部存储指针用于指向当前线程独有的数据区域，使程序能够快速访问线程私有变量

AAPCS32要求SP至少保持4字节对齐，并在公共函数调用边界即被调用函数开始执行时保持8字节对齐
.syntax unified
.cpu cortex-m3
.thumb

.global _start
.type _start, %function
.thumb_func

; 调用者
_start:
    ; 假设 SP 已初始化，并满足 AAPCS32 的 8 字节对齐要求

    ; 准备参数：
    ; 前四个参数通过 R0-R3 传递
    MOVS    R0, #1
    MOVS    R1, #2
    MOVS    R2, #3
    MOVS    R3, #4

    ; 为第五个参数分配栈空间
    ; 同时保证公共函数调用边界满足 8 字节对齐
    SUB     SP, SP, #8

    ; 第五个参数通过栈传递
    MOVS    R12, #5
    STR     R12, [SP, #0]

    ; 调用函数 calculate
    BL      calculate

    ; 清理栈参数区
    ; 返回值保存在 R0 中
    ADD     SP, SP, #8

end_loop:
    B       end_loop

.size _start, .-_start


.global calculate
.type calculate, %function
.thumb_func

; 被调用者
;
; 函数原型：
; int calculate(int a, int b, int c, int d, int e);
;
; 参数：
;   R0       = a
;   R1       = b
;   R2       = c
;   R3       = d
;   [入口SP] = e
;
; 返回值：
;   R0 = result
;
; 计算：
;   result = (a+b)*(c+d)+e

calculate:
    ; 保存被调用者需要保护的寄存器
    ; 同时保存 LR，避免后续调用覆盖返回地址
    PUSH    {R4-R6, LR}

    ; 读取第五个参数 e
    ; PUSH 保存4个寄存器，共占用16字节
    LDR     R4, [SP, #16]

    ; 计算 (a+b)*(c+d)+e
    ADD     R5, R0, R1
    ADD     R6, R2, R3
    MUL     R5, R5, R6
    ADD     R0, R5, R4

    ; 恢复寄存器并返回
    POP     {R4-R6, PC}

.size calculate, .-calculate

③AAPCS64

概述：规定AArch64的函数调用规则，采用满递减栈模型，即栈空间向低地址方向增长，SP始终指向当前栈顶位置

整数和指针类型参数优先通过X0-X7传递，浮点和向量类型参数优先通过V0-V7传递，当寄存器空间不足时，剩余参数通过栈传递

对于返回值，不超过64位的整数和指针通常通过X0返回，128位整数通常通过X0-X1返回

标量浮点数据或短向量类型通常通过V0返回，而HFA/HVA等复合浮点或向量类型可通过V0-V3返回

对于无法通过寄存器返回的大型结果类型，通常由调用者提供存储空间，并通过X8传递该存储空间地址，由被调用函数写入

AAPCS64规定调用者负责保存可能被覆盖 X0-X17和LR，被调用者负责保存需要保持不变的X19-X29和SP
类似地，X18部分平台中具有特殊用途，例如保存静态基址或线程局部存储指针，除非明确目标平台约定，否则不应随意修改
AAPCS64规定通过SP访问内存时，以及进入公共函数调用边界即被调用函数开始执行时，SP必须保持16字节对齐
.arch armv8-a

.text
.balign 4

.global _start
.type _start, %function


; 调用者
_start:

    ; 假设 SP 已初始化，并满足 AAPCS64 的 16 字节对齐要求

    ; 前8个64位整数参数通过 X0-X7 传递
    MOV     X0, #1
    MOV     X1, #2
    MOV     X2, #3
    MOV     X3, #4
    MOV     X4, #5
    MOV     X5, #6
    MOV     X6, #7
    MOV     X7, #8


    ; 第9个参数通过栈传递
    ; 额外分配16字节，保持SP 16字节对齐
    SUB     SP, SP, #16

    MOV     X9, #9
    STR     X9, [SP,#0]


    ; 公共函数调用边界
    ; 此时 SP 满足16字节对齐
    BL      calculate


    ; 清理栈参数区
    ; 返回值保存在 X0
    ADD     SP, SP, #16


end_loop:
    B       end_loop


.size _start, .-_start



.global calculate
.type calculate, %function


; 被调用者
;
; int64_t calculate(
;     int64_t a,b,c,d,e,f,g,h,i
; );
;
; 参数：
;   X0-X7    = a-h
;   [入口SP] = i
;
; 返回：
;   X0 = result
;
; result=(a+b)*(c+d)+e+f+g+h+i


calculate:

    ; 创建64字节栈帧
    ; 保存 FP(X29) 和 LR(X30)
    STP     X29, X30, [SP,#-64]!

    MOV     X29, SP


    ; 保存被调用者保存寄存器
    STP     X19, X20, [SP,#16]
    STP     X21, X22, [SP,#32]


    ; 函数入口SP位于当前FP上方64字节处
    ; 第9个参数位于 [X29,#64]
    LDR     X21, [X29,#64]


    ; 计算(a+b)*(c+d)
    ADD     X19, X0, X1

    ADD     X20, X2, X3

    MUL     X19, X19, X20


    ; 加上e、f、g、h、i
    ADD     X19, X19, X4
    ADD     X19, X19, X5
    ADD     X19, X19, X6
    ADD     X19, X19, X7

    ADD     X0, X19, X21


    ; 恢复被调用者保存寄存器
    LDP     X21, X22, [SP,#32]
    LDP     X19, X20, [SP,#16]


    ; 恢复FP、LR和SP
    LDP     X29, X30, [SP],#64


    ; 返回
    RET


.size calculate, .-calculate
