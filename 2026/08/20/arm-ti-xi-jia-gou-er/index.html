ARM体系架构（二）

指令系统

①简介

概述：Arm指令系统规定处理器执行指令的编码格式、操作数形式、寻址方式和执行效果，用于控制处理器完成各种操作

汇编语言使用便于阅读和编写的助记符表示机器指令，并可被汇编器转化为处理器能够执行的机器码
从语法和用途上看，汇编源文件通常包含标签、伪指令、数据定义、汇编器指令和处理器指令等内容

标签：用于指示代码或数据所在位置，本质是汇编器维护的符号，便于分支、函数调用和数据访问，如_start:

伪指令：一种没有对应机器编码的便捷写法，汇编器会根据实际情况将其转化为一条或多条实际处理器指令，如LDR R0, =value

数据定义：用于在目标文件中创建常量、字符串、数组或预留存储空间等数据内容，本身不会被处理器执行，如.space

汇编器指令：用于控制汇编过程，如指定代码段和数据段、符号可见性、对齐方式以及目标架构等，如.text

处理器指令：处理器能够直接执行的指令，其经过汇编后会生成对应的二进制编码，并由CPU完成译码和执行，如ADD

同一助记符可能因操作数形式不同而表示处理器指令或伪指令，如LDR R0, [R1]是处理器指令，而LDR R0, =value是伪指令
代码和数据需要根据执行流程正确组织，如果处理器执行路径进入.word等数据区域，可能将数据误认为指令执行，导致程序异常

②指令

概述：Arm的指令格式可抽象为指令助记符{后缀或限定符} 操作数列表，其中{}表示可选项

指令助记符表示操作类型，操作数表示参与运算的数据，可以是寄存器、立即数、内存地址或标签，具体数量和形式取决于指令
指令后缀用于指定条件执行、标志更新或数据处理方式，限定符用于补充编码形式、数据类型或操作数组织方式等信息

S后缀表示指令执行后更新相应的N/Z/C/V条件标志，条件后缀表示指令会根据条件标志决定是否执行，如EQ表示Z=1时执行

并非所有指令都会同时影响所有条件标志，具体更新哪些标志位取决于指令类型，有些指令如CMP无需S也会更新条件标志

T32某些指令同时存在16位和32位两种编码形式，可以使用宽度限定符显式指定编码宽度，其中.N/.W表示使用16/32位编码

后缀和限定符没有一套适用于所有Arm指令的固定组合，必须以目标指令集和对应指令的语法说明为准

如A32大部分数据处理指令都可以直接添加条件后缀，而T32的部分指令的条件执行需要配合IT块实现

A64取消了传统的条件后缀形式，条件分支通常采用点号形式或者将条件码作为操作数实现，如B.EQ和CSEL X0, X1, X2, EQ

③操作数

概述：操作数是指令的处理对象，用于输入数据、保存结果、计算内存地址或指定程序跳转目标

操作数可分为寄存器操作数、立即数操作数、内存操作数和标签操作数等，不同类型的操作数对应不同的数据来源和访问方式

寄存器操作数：表示数据存放在寄存器中，指令可以直接读取或修改寄存器中的数据，如ADD R0, R1, R2

立即数操作数：表示直接编码在指令中的常量数据，无需额外访问寄存器或内存，通常以#开头，如MOVS R0, #10

内存地址操作数：表示数据存放在指定内存中，指令通过地址访问对应的数据，通常使用方括号，如LDR R0, [R1]

标签操作数：使用符号名称表示代码或数据的位置，汇编器会根据标签对应的地址生成实际编码，如B loop

部分指令允许先对寄存器操作数进行移位或扩展后参与运算，内存操作数也可通过偏移或索引计算访问地址
寄存器范围、立即数编码形式和内存寻址方式都会受到目标指令集架构以及具体指令编码格式的限制

对于A32中的部分数据处理指令，立即数采用12位编码，由8位常数和4位旋转量组成

8位常数首先零扩展为32位，再将其循环右移旋转量两倍位数，得到最终参与运算的立即数

例如0x23000000可以由0x00000023循环右移8位得到，此时编码中的旋转量为4，对应的立即数编码为0x423

④内存寻址

概述：用于计算加载指令和存储指令实际访问的内存地址，通常由基址寄存器、偏移量和写回方式共同决定

常见寻址方式包括基址寻址、立即数偏移、寄存器偏移、缩放寄存器偏移、前变址、后变址以及多寄存器寻址等，如下所示
在A32和T32的部分加载指令中，还可以使用PC作为基址寄存器进行相对寻址，用于访问代码附近的常量池或只读数据
地址偏移量通常以字节为单位，其取值范围、可用寄存器类型和移位方式受具体指令及指令编码限制
;基址寻址：直接将基址寄存器中的值作为内存地址
LDR R0, [R1]                ; R0 = memory[R1]

;立即数偏移寻址：将基址寄存器与立即数偏移相加得到内存地址
LDR R0, [R1, #4]            ; R0 = memory[R1 + 4]
LDR R0, [R1, #-4]           ; R0 = memory[R1 - 4]

;寄存器偏移寻址：将基址寄存器与偏移寄存器相加得到内存地址
LDR R0, [R1, R2]            ; R0 = memory[R1 + R2]

;缩放寄存器偏移寻址：先对偏移寄存器进行移位，再与基址寄存器相加
LDR R0, [R1, R2, LSL #2]    ; R0 = memory[R1 + R2 * 4]

;前变址寻址：先计算新地址并写回基址寄存器，再使用新地址访问内存
LDR R0, [R1, #4]!           ; R1 = R1 + 4 随后 R0 = memory[R1]

;后变址寻址：先使用原基址访问内存，再更新基址寄存器
LDR R0, [R1], #4            ; R0 = memory[R1] 随后 R1 = R1 + 4

;多寄存器寻址：从连续内存中加载多个寄存器，或者将多个寄存器保存到连续内存中
LDMIA R0!, {R1-R4}           ; 连续加载多个寄存器
STMIA R0!, {R1-R4}           ; 连续存储多个寄存器
PUSH  {R4-R7, LR}            ; 将多个寄存器压入栈
POP   {R4-R7, PC}            ; 从栈中恢复多个寄存器

⑤Hello Arm

概述：以下分别通过Linux系统调用和C标准库输出Hello Arm!，面向32位AArch32 Linux环境

由于两个程序均运行在AArch32 Linux用户态，Linux内核已提前准备运行环境，如果是裸机程序则通常需要由启动代码完成

运行环境初始化通常包括创建并设置栈空间、初始化内存区域如BSS段和Data段、设置程序入口以及建立必要的系统服务接口

如果需要使用C库，用户代码入口应定义为main，真正的程序入口由C运行时负责，运行时完成环境初始化后再调用main

C运行时是一组支持C程序运行的启动代码和运行库，负责在调用main前完成环境初始化，并在程序结束时进行清理

使用C库时应由C Runtime提供入口_start，程序直接定义_start会跳过运行时初始化，导致libc环境未建立出现异常
系统调用编号与ABI相关，本例仅适用于AArch32 Linux，直接用于AArch64或裸机环境将无法正常运行
# 运行系统调用版本
sudo apt update
sudo apt install gcc-arm-linux-gnueabihf \
    binutils-arm-linux-gnueabihf \
    libc6-dev-armhf-cross \
    qemu-user
arm-linux-gnueabihf-as -o hello.o hello.s
arm-linux-gnueabihf-ld -e _start -o hello hello.o
qemu-arm ./hello

# 运行 C 标准库版本
arm-linux-gnueabihf-gcc -static -no-pie -o hello_c hello_c.s
qemu-arm ./hello_c
@ 系统调用版本
.syntax unified    @ 指定使用统一汇编语法UAL
.arch armv7-a      @ 目标处理器架构是 ARMv7-A
.arm               @ 当前状态为ARM状态

@ 切换到只读数据段，并定义一个标签 msg 用于存放 "Hello Arm!\n"
@ 随后定义一个常量 len，其值为当前地址 . 即字符串结束地址减去 msg 即字符串起始地址，即字符串长度
.section .rodata
msg:
    .ascii "Hello Arm!\n"
.equ len, . - msg

@ 切换到代码段，并定义一个全局符号 _start，告诉汇编器和链接器 _start 这个符号属于函数类型
.section .text
.global _start
.type _start, %function

_start:
    @ write(1, msg, len)，其中 R0-R2 用于传递参数，R7用于传递系统调用号，最后通过 SVC 指令触发系统调用
    MOV R0, #1
    LDR R1, =msg
    MOV R2, #len
    MOV R7, #4
    SVC #0

    @ exit(0)，类似地，R0 用于传递参数，R7用于传递系统调用号，最后通过 SVC 指令触发系统调用
    MOV R0, #0
    MOV R7, #1
    SVC #0

@ 记录 _start 符号对应代码区域的大小，供链接器和调试工具使用
.size _start, . - _start

@ 告诉链接器该程序不需要可执行栈，使最终生成的程序栈默认不可执行，提高安全性
.section .note.GNU-stack,"",%progbits
@ C库版本
.syntax unified    @ 指定使用统一汇编语法 UAL
.arch armv7-a      @ 指定目标处理器架构为 ARMv7-A
.arm               @ 指定当前使用 ARM 状态

@ 切换到只读数据段，并定义标签 msg 保存字符串 "Hello Arm!"
@ .asciz 会在字符串末尾自动添加字符串结束符 '\0'，符合 C 字符串格式
.section .rodata
msg:
    .asciz "Hello Arm!"

@ 切换到代码段，定义全局函数 main
@ .global 使 main 符号可以被链接器访问
@ .type 告诉汇编器和链接器，main 是一个函数符号
@ .extern 声明外部函数 puts，该函数由 C 标准库提供
.section .text
.global main
.type main, %function
.extern puts

main:

    @ 保存被调用函数需要保护的寄存器
    @ BL 指令会修改 LR，因此调用其他函数前需要保存 LR
    @ 同时保存两个寄存器（8字节），使 SP 保持 AAPCS 要求的8字节对齐
    PUSH {R4, LR}

    @ 调用 C 标准库函数 puts("Hello Arm!")
    @ 根据 AAPCS 调用约定，第一个参数通过 R0 传递
    @ LDR 将字符串地址加载到 R0
    @ BL 调用 puts，并将返回地址保存到 LR
    LDR R0, =msg
    BL puts


    @ main 返回 0
    @ C 语言中 main 的返回值通过 R0 返回给调用者
    MOV R0, #0


    @ 恢复之前保存的寄存器，并返回调用者
    @ POP {R4, PC} 会恢复 R4，同时将保存的返回地址加载到 PC，实现函数返回
    POP {R4, PC}

@ 记录 main 函数对应代码区域的大小，供链接器和调试工具使用
.size main, . - main


@ 告诉链接器该程序不需要可执行栈，使最终生成的程序栈默认不可执行，提高安全性
.section .note.GNU-stack,"",%progbits
