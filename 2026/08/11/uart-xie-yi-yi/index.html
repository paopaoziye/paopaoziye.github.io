UART协议（一）

协议简介

①引言

概述：也称为通用异步收发器，是一种常用的异步全双工串行通信方式，主要用于设备间的点对点数据传输，采用LSB First

典型UART至少由TX、RX和GND三根信号线组成，分别用于发送数据、接收数据和提供电平参考，通信时发送端TX连接接收端RX

STM32等芯片中常见的串行通信外设为USART，不仅支持UART的异步通信模式，还支持通过CK输出同步时钟

USART通常还提供RTS和CTS进行硬件流控，用于控制发送端暂停或继续发送数据，避免接收端因处理不及时而发生数据溢出

UART硬件结构简单且开发成本较低，还可配合RS-232和RS-485等物理层接口，提高传输距离和抗干扰能力

MCU的UART/USART引脚通常直接使用MCU GPIO的逻辑电平，具体输入电平阈值以数据手册中的VIH、VIL参数为准

UART信号经过RS-232收发器会被转换为RS-232电气信号，其逻辑0由+3V~+15V表示，逻辑1由-3V~-15V表示

UART信号经过RS-485收发器会被转化为对应的差分信号A和B，使用A、B两根线之间的电压差表示逻辑信号

UART通信速率、传输距离和抗干扰能力有限，且本身缺少设备寻址、总线仲裁和多节点管理机制，不适合高速复杂网络通信

②帧格式

概述：典型的UART数据帧由起始位、数据位、校验位和停止位组成，并以设定的波特率传输

UART最常见的数据格式为8N1，即8个数据位、无校验和1个停止位，此时UART发送一个字节需要传输10 bit

起始位：UART总线空闲时通常保持逻辑1，发送端发送一位逻辑0产生起始信号通知接收端一帧新的数据即将开始

数据位：长度为5-9bit，通常采用LSB First，即低位先发送，如果启用了校验则校验位为数据位的最后一位

校验位：用于对数据进行简单的错误检测，常见的方式为无校验、奇校验和偶校验，偶校验即数据位和校验位中1的数量为偶数

停止位：固定为逻辑1，用于表示当前数据帧结束，常见长度为1 bit、1.5 bit和2 bit，后续没有新的数据总线会进入空闲状态

UART通过预设波特率确定每个bit的时间，并在检测到起始位后通过过采样在各数据位中心进行采样，实现无时钟线的异步通信
通信双方必须配置一致，包括波特率、数据位、校验位和停止位等，否则可能导致乱码、校验错误或帧错误

③发送流程

概述：UART的发送流程为CPU -> TDR -> TX FIFO -> TX Shift Register -> TX Pin，其中部分UART外设可能不提供TX FIFO

CPU将数据写入发送数据寄存器TDR，经过TX FIFO缓冲后进入TX Shift Register，最后按照设定的帧格式和波特率从TX Pin中输出

在UART发送过程中，可通过TXE、TXFNF、TC和TXFE等标志位判断发送缓冲区是否可写以及数据是否已经真正发送完成

TXE表示TDR为空，TXFNF表示TX FIFO未满，TC表示整个发送过程完成，TXFE表示TX FIFO已空

TX FIFO的作用是暂存多个待发送字节，减少CPU等待，提高连续发送效率，并且硬件会自动添加起始位、停止位和可选的校验位
真正负责逐位发送的是TX Shift Register，TXE/TXFNF仅表示可以继续写入数据，而TC才表示移位寄存器中的最后一帧发送完成

④接收流程

概述：UART的接收流程通常为RX Pin -> RX Shift Register -> RX FIFO -> RDR -> CPU，其中部分UART外设可能不提供RX FIFO

RX Pin接收数据后，经RX Shift Register逐位采样并还原数据，经RX FIFO缓冲后写入接收数据寄存器RDR，最后由CPU读取

在UART接收过程中，可通过RXNE、RXFNE和RXFF等标志位判断接收缓冲区状态以及数据是否已经真正接收完成

RXNE表示RDR中存在待读取数据，RXFNE表示RX FIFO非空，RXFF表示RX FIFO已满

RX FIFO用于暂存已接收数据，为CPU提供处理时间，从而降低连续接收过程中发生数据丢失的风险
若每接收一个字节就触发一次中断，会显著加重CPU负担，可以采用FIFO并设置接收阈值批量处理数据，降低中断频率与CPU开销

⑤错误标志

概述：UART在接收过程中可通过PE、FE、NE和ORE等错误标志判断是否发生校验错误、帧错误、噪声错误或接收溢出

错误标志用于检测并定位UART接收过程中的异常状态，便于软件及时处理并避免错误继续影响后续通信

PE：表示接收数据的奇偶校验结果与设定规则不一致，通常由校验配置不匹配或线路干扰引起

FE：表示在预期的停止位位置未检测到有效停止位，通常由波特率不匹配、帧格式配置错误或信号干扰引起

NE：表示接收过程中检测到噪声干扰或异常电平变化，通常与线路质量差、外部干扰或信号边沿异常有关

ORE：表示旧数据尚未及时读取时新数据再次到达，发生接收溢出，通常由CPU处理不及时或接收速率过高引起

错误标志能够帮助软件快速定位异常来源，区分参数配置、线路质量和数据处理等问题，并针对性地进行重传、丢弃或恢复处理
发生错误后应及时读取并清除对应状态标志，否则可能影响后续数据接收，具体清除方式以芯片参考手册为准

⑥串口协议帧

概述：在UART字节流之上，按照约定格式组织数据和控制信息的一条完整消息，XMODEM就是一种典型的串口文件传输协议

UART只负责逐字节传输，而XMODEM在此基础上定义了数据块格式、校验、确认、重传和结束机制，用于实现可靠的文件传输

XMODEM将待传输文件划分为多个固定大小的数据块，经典版本的基本格式为SOH | Block No | ~Block No | Data(128B) | CRC16

SOH：固定值为0x01，用于标识一个新的XMODEM数据块的起始位，接收端检测到SOH后会按固定格式继续解析后续字段

Block No：长度为1 Byte的块编号，用于标识当前数据块的传输顺序，接收端可据此判断数据块是否发生重复、丢失或乱序

~Block No：长度为1 Byte，其值为Block No的按位取反值，满足Block No + ~Block No = 0xFF，用于检查块编号是否正确

Data：用于承载实际文件内容的数据区，发送端按固定大小分块传输文件，接收端再按Block No重新拼接

CRC16：长度为2 Byte，发送端根据Data计算校验值，接收端重新计算并比对，用于判断数据在传输过程中是否发生错误

XMODEM不仅规定数据帧格式，还通过ACK/NAK确认、超时检测和自动重传机制，降低数据丢失或传输错误的风险
经典XMODEM每个数据块固定为128 Byte，若最后一个数据块不足 128 Byte，通常需要使用约定字符进行填充，使其达到固定长度
