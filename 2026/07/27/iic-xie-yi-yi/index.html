IIC协议

IIC协议（一）

协议简介

①引言

概述：也称为集成电路总线，是一种常用的同步半双工串行通信方式，主要用于短距离、中低速的多设备通信，采用MSB First

典型IIC由SCL和SDA线组成，前者用于传输时钟信号，后者用于传输数据信号，并且IIC将设备分为主设备和从设备

主设备：负责发起通信并产生时钟信号，通过发送从机地址选择需要通信的设备，同时决定本次通信是读还是写

从设备：持续监听总线地址，在地址匹配后通过ACK响应主设备，并按照主设备指定的读写方向完成数据接收或发送

SCL和SDA通常采用开漏输出结构，设备只能主动拉低总线或释放总线，高电平由外部上拉电阻提供，从而实现逻辑线与

开漏结构让所有设备不能主动拉高总线，因此多个设备可以安全共享同一根SDA和SCL，并实现总线仲裁和时钟拉伸

逻辑线与：当所有设备都释放总线时，总线被上拉电阻拉到高电平，当任意一个设备输出低电平时，总线变为低电平

总线仲裁：主机发送逻辑1时发现总线实际为低电平，就知道有其他主机正在拉低总线，于是判定自己失去仲裁并停止发送

时钟拉伸：当从机暂时无法继续处理数据时，可以在主机释放SCL后继续将其拉低并保持低电平，使主机暂停后续通信

IIC总线必须具有合适的上拉电阻，上拉电阻过大会导致信号上升沿过慢，上拉电阻过小则会增加低电平状态下的灌电流和功耗

②帧格式

概述：典型的IIC通信帧由起始信号、从机地址、读写位、应答位、数据段和停止信号组成，并以设定的通信速率传输

一次典型通信可以表示为START -> Address + R/W -> ACK -> Data -> ACK -> ... -> STOP，总线空闲时SCL和SDA均为高电平

起始信号：当SCL保持高电平时，SDA由高电平变为低电平，通知总线上的所有从设备一次新的通信即将开始

从机地址：用于选择当前需要通信的从设备，通常是7 bit从机地址，随后再发送1 bit的读写位，可以整体视作为第一个数据段

读写位：用于指定本次通信的数据传输方向，R/W = 0表示主设备向从设备写数据，R/W = 1表示主设备从从设备读数据

应答位：每传输完8 bit数据后，第9个时钟用于应答；ACK = 0表示接收方应答，NACK = 1表示未应答或不再继续接收

数据段：长度为8 bit，通常采用MSB First，即高位先发送，每传输完一个字节后，接收方都会在第9个时钟周期应答

停止信号：当SCL保持高电平时，SDA由低电平变为高电平，表示当前通信结束并释放总线

主设备在不发送停止信号且不释放总线的情况下，再次产生一个START条件，用于在同一次通信过程中重新寻址或切换读写方向
发送方在传输完8 bit后释放SDA，由接收方在第9个时钟周期产生ACK/NACK，发送方通过监听SDA电平判断应答结果
传输数据和ACK/NACK应答位时，SDA只能在SCL为低电平时改变状态，并在SCL为高电平时保持稳定以保证接收方能够正确采样

③发送流程

概述：IIC的发送流程为CPU -> TXDR -> TX FIFO -> TX Shift Register -> SDA，其中部分IIC外设可能不提供TX FIFO

发送开始前主设备需要通过控制寄存器CR2配置从机地址、读写方向、传输长度以及START、AUTOEND、RELOAD等传输控制信息

在IIC发送过程中，可以通过BUSY、TXIS、NACKF、TC、TCR和等STOPF标志位判断总线状态和发送结果

BUSY表示总线处于忙状态，TXIS表示TXDR可以写入新的发送数据，NACKF表示接收到NACK，STOPF表示检测到停止信号

TC表示当前配置的一段传输已经完成，等待软件产生停止信号结束通信或重新配置CR2后产生Repeated START开启新的传输

TCR表示当前一段传输完成后进入重载阶段，此时总线仍保持通信状态，需要重新配置下一段传输的NBYTES等参数

连续发送多个字节时，通常只需要在TXIS置位后不断向TXDR写入数据，无需每发送一个字节都重新配置CR2
TC只表示当前配置的一段传输完成，并不一定表示整个IIC通信结束，只有产生STOP并置位STOPF后，才表示本次通信已经结束

④接收流程

概述：IIC的接收流程为SDA -> RX Shift Register -> RX FIFO -> RXDR -> CPU，其中部分IIC外设可能不提供RX FIFO

主设备接收前同样需要配置控制寄存器CR2并完成从机寻址，但需要将传输方向设置为读，随后由从设备向主设备发送数据

接收过程中最主要的状态标志为RXNE，表示RXDR中已经存在待读取数据，CPU读取后硬件继续接收后续数据

连续接收多个字节时，主设备对前面的字节返回ACK表示继续接收，对最后一个字节返回NACK表示结束接收

支持NBYTES的STM32 IIC外设通常可以由硬件自动完成该过程，并在启用AUTOEND时自动产生停止信号

主设备接收时，如果RXDR未及时读取，IIC外设通常会暂停SCL等待CPU处理，读取完成后再继续接收后续数据

⑤错误标志

概述：IIC可以通过BERR、ARLO、OVR和TIMEOUT等错误标志判断是否发生总线错误、仲裁丢失、数据溢出和通信超时

IIC发生异常时，硬件会置位对应的错误标志，CPU可通过读取状态寄存器判断当前故障类型

BERR：表示检测到总线时序错误，例如通信过程中出现不符合协议要求的起始信号和停止信号

ARLO：表示主设备在多主机仲裁过程中检测到发送电平与实际总线电平不一致，从而失去总线控制权

OVR：表示发生接收溢出或发送欠载，通常出现在从机模式且禁止时钟拉伸时，CPU未及时读取RXDR或写入TXDR

TIMEOUT：表示总线状态长时间未发生预期变化，可能由从设备长时间拉低时钟、总线锁死或设备异常引起

多个错误标志可能同时出现，实际排查时应结合当前通信阶段和总线电平状态共同判断异常原因
多数错误标志在异常发生后会被硬件锁存，需要软件按照芯片参考手册规定的方式清除，否则可能影响后续通信

⑥总线锁死

概述：指SDA或SCL被从设备持续拉低，导致总线无法恢复到空闲状态，使主设备无法正常产生新的起始信号并继续通信

常见原因是通信过程中主设备异常复位、掉电或传输被中断，而从设备仍停留在原来的通信状态并继续占用总线

SDA锁死：从设备仍认为当前传输尚未结束，因此持续拉低SDA，主设备无法重新产生正常的起始信号

SCL锁死：从设备持续拉低SCL，可能是异常的时钟拉伸或设备内部状态异常引起，使主设备无法继续产生时钟信号

当SDA持续被拉低时，主设备可临时将SCL配置为GPIO，主动产生最多约9个时钟脉冲，使从设备继续运行并释放SDA

因为一个IIC字节通常由8 bit数据和1 bit应答组成，因此9个SCL时钟脉冲通常可以使卡在字节传输中的从设备完成传输

总线恢复前应先判断是SDA还是SCL被持续拉低，若SCL本身无法释放，说明从设备仍在持续占用时钟线，通常需要复位从设备
