SPI协议（一）

协议简介

①引言

概述：也称为串行外设接口，是一种常用的同步全双工串行通信方式，主要用于MCU与外围器件之间的短距离高速通信

典型SPI通常由SCLK、MOSI、MISO和CS/NSS四根信号线组成，分别用于提供同步时钟、发送数据、接收数据和片选

SPI将设备分为主设备和从设备，前者负责产生时钟信号并控制片选信号，后者主要根据前者提供的时钟完成数据收发

CS/NSS为片选信号，通常由主机控制且低电平有效，主机通过拉低对应CS选择从设备，通信结束后再将其拉高

SPI结构简单、协议开销较小，支持较高的通信速率和全双工数据传输，适合MCU与高速外设之间进行高效的数据交换
SPI缺少统一的设备寻址、错误校验和总线仲裁机制，连接多个从设备时通常需要增加独立片选线，不适合复杂的多节点通信场景

②帧格式

概述：SPI没有统一固定的帧格式，一次通信通常由CS有效开始，在SCLK驱动下连续传输若干位数据，并在CS失效后结束

SPI本身主要规定基本的数据传输时序即时钟极性CPOL、时钟相位CPHA、传输顺序和数据宽度，保证主从设备安全完成数据交互

时钟极性规定SCLK在空闲状态下保持高电平还是低电平，时钟相位规定数据在SCLK的第一个还是第二个有效边沿进行采样

传输顺序规定数据按MSB First还是LSB First逐位发送，数据宽度规定一次基本传输包含的有效数据位数，如8 bit或16 bit

SPI对帧内容限制较少，不同外设可以根据自身需求灵活定义命令、地址和数据等字段，具体结合对应的数据手册确定实际通信格式

以W25Q64存储器为例，其读数据指令通常为03H:[24位地址]:[数据]，其中03H为读操作码

主从设备的CPOL、CPHA、传输顺序和数据宽度必须保持一致，否则可能导致数据错位或通信异常

③收发流程

概述：SPI采用全双工同步通信，主机在产生SCLK的同时，通过MOSI发送数据，并通过MISO同步接收从机返回的数据

SPI收发本质上是主从设备的移位寄存器随SCLK同步移位，每个时钟周期同时完成一位数据的发送和接收

SPI收发流程为CPU -> TXDR -> TX FIFO -> TX Shift Register -> MOSI和MISO -> RX Shift Register -> RX FIFO -> RXDR -> CPU

SPI收发过程中，可通过TXE、TXP、RXNE、RXP、RXWNE和BSY/EOT等标志位判断收发缓冲区状态及传输是否完成

TXE表示发送数据寄存器为空，TXP表示TX FIFO中存在可写空间，RXNE表示接收数据寄存器非空

RXWNE表示RX FIFO中至少存在一个完整的数据字，BSY表示SPI当前仍处于数据传输状态，EOT表示本次配置的数据传输结束

TX/RX FIFO可在CPU与移位寄存器之间缓存数据，减少CPU频繁访问数据寄存器的开销，但是不是所有SPI都支持TX/RX FIFO
SPI接收数据时仍需要主机持续产生SCLK，因此纯接收场景下通常也需要发送Dummy Data以提供传输时钟

④错误标志

概述：SPI在通信过程中可通过OVR、UDR和MODF等错误标志判断是否发生接收溢出、发送下溢和模式冲突

常见SPI错误主要集中在收发缓冲、主从模式和总线状态等方面，可结合对应标志位进行定位

OVR：表示旧的接收数据尚未及时读取时新的数据再次到达即发生接收溢出，通常由CPU处理不及时或接收速率过高引起

UDR：表示需要发送数据时发送端未及时提供新的数据即发生发送下溢，通常由数据准备不及时或从机响应速度不足引起

MODF：表示SPI发生主从模式冲突，通常与主机模式下NSS/CS状态异常或多个主设备同时驱动总线有关

SPI协议本身不规定CRC校验，但部分SPI控制器支持硬件CRC功能，启用后可通过CRCERR等标志判断是否发生CRC校验错误
不同SPI控制器支持的错误类型并不完全一致，部分标志仅在特定工作模式或功能开启后才会产生

⑤功能扩展

概述：为了减少引脚数量或提高数据吞吐率，SPI又发展出了3-Wire SPI、Dual SPI、Quad SPI和OctoSPI等扩展形式

3-Wire SPI主要用于减少引脚占用，而Dual/Quad/OctoSPI主要通过增加并行数据线提高单位时钟周期的数据传输能力简洁一点

3-Wire SPI：将MOSI和MISO合并为一根双向数据线SDIO，以减少引脚占用，变为半双工通信

Dual SPI、Quad SPI和OctoSPI分别使用2、4、8根数据线并行传输，以提高单位时钟周期的数据传输能力

Dual/Quad/OctoSPI可在指令、地址和数据阶段使用不同数量的数据线，并可结合DDR/DTR进一步提高传输带宽
3-Wire SPI、Dual SPI、Quad SPI和OctoSPI并非所有设备都支持，具体的数据线切换、Dummy Cycle和时钟要求需参考芯片手册
