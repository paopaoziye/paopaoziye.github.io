# 处理器架构
## Arm体系架构
### Arm体系架构（一）
#### 1.引言
**①简介**
>**概述**：`Arm`是一种以**精简指令集**思想为基础的处理器架构家族，具有较高的**执行效率**和**能效**
{%list%}
Arm体系架构是一种处理器的行为规范，规定指令集、寄存器、内存访问、异常与中断和特权级等内容
{%endlist%}
>`Arm`体系架构一般不规定**流水线级数**、**缓存大小**和**主频**等具体硬件实现细节
{%right%}
Arm主要提供A、R和M三类架构Profile，分别面向应用处理器、实时处理器和微控制器处理器
{%endright%}
>每种系列又有`Armv7`、`Armv8`、`Armv9`等不同版本，如`Armv8-A`、`Armv8-R`和`Armv8-M`等

>通常`R-Profile`和`M-Profile`只有`MPU`，只提供**内存区域保护**而不能提供**虚拟地址到物理地址的转换**
{%warning%}
Cortex-A/R/M是Arm公司依据相应架构Profile设计的处理器核系列，属于架构规范的具体处理器核实现
{%endwarning%}
>比如`Cortex-M33`实现了`Armv8-M`、`Cortex-A53/A72`实现了`Armv8-A`、`Cortex-R52`实现了`Armv8-R`


**②执行状态**
>**概述**：`Arm`主要定义了`AArch32`和`AArch64`两种执行状态，支持哪种状态取决于**架构`Profile`**和**处理器**
{%list%}
执行状态决定处理器所采用的指令集、寄存器模型以及相应的特权与异常处理模型等
{%endlist%}
>`AArch32`状态使用`A32`或`T32`指令集，`AArch64`使用`A64`指令集

>`AArch32`状态使用`32`位通用寄存器，`AArch64`使用`64`位通用寄存器
{%right%}
在同时支持AArch32和AArch64的处理器中，两种执行状态之间通常通过异常进入或异常返回过程切换
{%endright%}
{%warning%}
M-profile不采用AArch32/AArch64这套执行状态分类，采用32位程序员模型，并仅支持T32指令集
{%endwarning%}
**③指令集**
>**概述**：`Arm`体系架构主要包括`A32`、`T32`和`A64`三种指令集
{%list%}
A32的指令编码固定为32位，T32指令编码混合使用16位和32位，A64的每条指令编码固定为32位
{%endlist%}
>`T32`由`Thumb`演进而来，通过引入`Thumb-2`技术，形成了混合使用`16`位和`32`位编码的指令体系

>`A32/T32`以`32`位通用运算为主，也支持部分`64`位操作；`A64`同时原生支持`64`位和`32`位通用运算
{%right%}
A32指令规整，便于处理器取指、译码和执行，且功能成熟，能够兼容大量传统Arm32位程序
{%endright%}
>`T32`在兼顾指令功能的同时具有**较高的代码密度**，适合存储资源受限的嵌入式系统

>`A64`具有**更大的地址空间**以及**更多通用寄存器**，适合现代高性能计算系统
{%warning%}
A32和T32可以在同一个AArch32程序中协同使用，需要通过特定的分支指令完成指令集状态切换
{%endwarning%}
{%wrong%}
A64不能与A32或T32指令直接混合执行，程序通常需要针对AArch64重新适配与编译
{%endwrong%}
#### 2.寄存器模型
**①32位寄存器模型**
>**概述**：通常提供`16`个`32`位程序员可见的寄存器`R0-R15`和当前程序状态寄存器`CPSR`，如下图所示
{%list%}
R0-R12为通用寄存器，R13为栈指针寄存器SP，R14为链接寄存器LR，R15为程序计数器
{%endlist%}
>`R0-R12`主要用于**数据运算和地址计算**，还需要遵循`AAPCS32`约定

>`SP`指向当前**栈顶**，栈主要用于保存**函数局部变量**、**函数调用现场**、**中断现场**和**任务上下文**等

>`LR`通常保存**函数调用**或**异常处理**所需的返回信息，当函数和异常结束后可以通过`BX LR`返回

>`PC`用于控制处理器的**指令执行位置**，**分支**、**调用**、**返回和部分加载指令**可以更新`PC`以改变程序控制流

>`CPSR`用于保存**当前处理器状态**，包括**条件标志位**、**当前执行状态**、**中断屏蔽位**和**处理器模式**等
{%right%}
部分异常模式拥有银行化寄存器，可以快速保存和切换关键现场，减少软件保存开销
{%endright%}
>**银行化寄存器**即处理器**切换模式**后，对应的寄存器编号会自动映射到**另一组物理寄存器**

>`SPSR`用于保存`CPSR`，因为**异常发生时**处理器需要改变`CPSR`，将其保存到`SPSR`，直到**异常返回**再恢复
{%warning%}
如果函数内部还需要继续调用其它函数，LR可能会被覆盖，所以通常需要将其保存到栈中
{%endwarning%}
**②64位寄存器模型**
>**概述**：通常提供`31`个`64`位通用寄存器`X0-X30`、栈指针寄存器`SP`、零寄存器`XZR`和程序状态`PSTATE`
{%list%}
每个通用寄存器还可通过W0-W30访问其低32位，但是对Wn的写入会把对应Xn的高32位自动清零
{%endlist%}
>`X29`通常作为帧指针`FP`，用于定位**当前函数的栈帧**，`X30`为链接寄存器`LR`

>`SP`不属于通用寄存器，只能在**部分指令编码**中使用

>`XZR`读取时恒为`0`，写入时**结果被丢弃**，可以避免为了读取常量`0`而额外分配一个真实寄存器

>`AArch64`没有对应`AArch32 CPSR`的单一可见寄存器，而是使用一组**程序状态字段**，统称为`PSTATE`
{%right%}
与AArch32不同，AArch64中的程序计数器由处理器内部维护，这样使指令编码和流水线行为更加规整
{%endright%}
>`AArch64`中不同异常级别通常有**各自的状态保存寄存器**用于保存异常前的`PSTATE`和**返回地址**

>`AArch64`还提供`32`个`128`位浮点寄存器`V0-V31`，可用于**浮点运算**、**向量运算**、**加密和媒体处理**等
{%warning%}
X29作为帧指针属于调用约定，在不需要栈回溯或编译器省略帧指针时，X29也作为普通寄存器使用
{%endwarning%}
{%wrong%}
AArch64中寄存器编号X31的含义取决于具体指令，可能为栈指针寄存器SP也可能为零寄存器XZR
{%endwrong%}
**③M-profile寄存器模型**
>**概述**：`M-profile`也采用`32`位寄存器模型，但是针对`MCU`和**实时控制**进行了简化
{%list%}
将程序状态拆分到xPSR中，并采用PRIMASK、BASEPRI、FAULTMASK和CONTROL完成中断和权限管理
{%endlist%}
>`xPSR`可分为`APSR`、`IPSR`和`EPSR`，分别用于记录**程序状态**、**当前异常编号**和**指令执行状态**

>`CONTROL`用于控制`Thread mode`的部分运行状态如**特权级**、使用`MPS/PSP`以及**浮点上下文状态**

>`PRIMASK`用于屏蔽所有**可配置优先级**的异常，但不包括`NMI`和`HardFault`

>`BASEPRI`用于设置一个**优先级阈值**，屏蔽**优先级数值大于等于该值**的所有可配置异常

>`FAULTMASK`用于屏蔽除了`NMI`以外的所有异常，包括`HardFault`
{%right%}
M-profile实际有两个栈指针MSP和PSP，前者常用于启动代码、异常和中断，后者常用于RTOS线程
{%endright%}
>在`Thread mode`下可以通过`CONTROL.SPSEL`选择使用哪一个栈指针，但是`Handler mode`始终使用`MSP`
{%warning%}
M-profile没有银行化寄存器，但是进入异常时，硬件会自动保存一部分现场到对应的栈中
{%endwarning%}
{%wrong%}
不同的Cortex-M处理器实现的特殊寄存器并不完全相同，比如Cortex-M0不提供BASEPRI和FAULTMASK
{%endwrong%}
#### 3.过程调用标准
**①简介**
>**概述**：过程调用标准`PCS`为`ABI`的重要组成部分，用于规定**调用者与被调用者**之间的接口约定
{%list%}
过程调用标准规定参数和返回值的传递方式、调用者与被调用者的寄存器保存责任、栈的组织和对齐等
{%endlist%}
>`Arm`主要提供面向`AArch32`的`AAPCS32`和面向`AArch64`的`AAPCS64`

>`ABI`规定程序编译为机器码后，不同**目标文件**、**库和程序模块**如何相互配合

>`ABI`通常还涉及**数据类型布局**、**目标文件格式**、**符号链接**和**异常展开**等内容

{%right%}
高级语言编译器通常会根据目标平台和编译选项自动遵循相应的过程调用标准
{%endright%}
{%warning%}
汇编代码与编译器生成的代码交互时，也必须遵守相同标准，且不同模块还应采用兼容的ABI变体
{%endwarning%}
{%wrong%}
AAPCS不规定处理器的硬件异常入口和返回机制，但异常处理程序中的普通函数调用仍须遵循AAPCS
{%endwrong%}
**②AAPCS32**
>**概述**：`AAPCS32`采用**满递减栈**即栈向低地址增长，`SP`指向栈有效空间**最低地址**
{%list%}
使用R0-R3传递参数，如果寄存器空间不足，使用栈传递参数，对于64位参数，采用R0-R1或R2-R3传递
{%endlist%}
>对于**返回值**，不超过`32`位使用`R0`，`64`位使用`R0-R1`，`128`位的**容器化向量**使用`R0-R3`

>如果返回值为**较大的结构体**，通常需要通过**调用者提供的内存**间接返回
{%right%}
AAPCS32规定调用者需要保存R0-R3、R12和LR，被调用者需要保存R4-R11和SP
{%endright%}
>**调用者**需要保存`LR`是因为其会被**函数调用指令**如`BL`和`BLX`改写覆盖

>**被调用者**需要保存`R9`是建立在`R9`作为**普通的被调用者保存寄存器**使用为前提的
{%warning%}
R9在一些平台可能用于保存平台专用数据，除非明确知道目标平台约定，否则尽量不要使用R9
{%endwarning%}
>`R9`可能被用于保存**静态基址**或**线程局部存储指针**，也可能被当作**普通被调用者保存寄存器**
{%wrong%}
AAPCS32规定SP始终应保持4字节对齐，并在公共函数调用边界保持8字节对齐
{%endwrong%}
>**公共函数调用边界**指调用者把参数准备好并执行调用，被调用函数刚开始执行的那个交界位置
```arm-gas
.syntax unified
.cpu cortex-m3
.thumb

.global _start
.type _start, %function
.thumb_func
;调用者-主程序
_start:
    ; 假设SP已经初始化并保持8字节对齐

    ; 准备参数，前四个参数通过 R0-R3 传递
    MOVS    R0, #1
    MOVS    R1, #2
    MOVS    R2, #3
    MOVS    R3, #4

    ; 分配8字节参数区，其中4字节作为对齐填充
    ; 因为马上就是公共函数调用边界，SP需要8字节对齐
    SUB     SP, SP, #8
    MOV.W   R12, #5
    STR     R12, [SP, #0]
    
    ; 调用函数calculate
    BL      calculate

    ; 清理栈空间，并且此时 R0 中保存了返回值
    ADD     SP, SP, #8

end_loop:
    B       end_loop

.type calculate, %function
.thumb_func

; 被调用者
;
; 函数原型：
; int calculate(int a, int b, int c, int d, int e);
;
; 参数：
;   R0       = 第一个参数a
;   R1       = 第二个参数b
;   R2       = 第三个参数c
;   R3       = 第四个参数d
;   入口[SP] = 第五个参数e
;
; 计算：
;   result = (a+b)*(c+d)+e
;
; 返回值：
;   R0 = result
calculate:
    ; 保存需要使用的被调用者保存寄存器
    PUSH    {R4-R6, LR}      
    
    ; 从栈中读取第五个参数
    LDR     R4, [SP, #16]    

    ; 计算返回值为(1+2)*(3+4)+5=26，并将其保存到R0中
    ADD     R5, R0, R1
    ADD     R6, R2, R3
    MUL     R5, R6, R5
    ADD     R0, R5, R4       

    ; 恢复保存的寄存器
    POP     {R4-R6, PC}
```
**③AAPCS64**
>**概述**：`AAPCS64`采用**满递减栈**即栈向低地址增长，`SP`指向有效栈空间**最低地址**
{%list%}
整数和指针参数优先使用X0-X7传递，浮点和向量参数优先使用V0-V7传递，寄存器空间不足则使用栈
{%endlist%}
>不超过`64`位的**整数和指针**返回值通常使用`X0`，`128`位整数使用`X0-X1`

>**标量浮点或短向量**返回值使用`V0`，`HFA/HVA`可使用`V0-V3`

>不能通过寄存器返回的**大型结果**通过`X8`指定的内存间接返回

{%right%}
AAPCS32规定调用者需要保存X0-X17和LR，被调用者需要保存X18-X29和SP，详细如下所示
{%endright%}
>**调用者**需要保存`LR`是因为其会被**函数调用指令**如`BL`和`BLX`改写覆盖

>**被调用者**需要保存`X18`是建立在`X18`作为**普通的被调用者保存寄存器**使用为前提的
{%warning%}
X18在一些平台可能用于保存平台专用数据，除非明确知道目标平台约定，否则尽量不要使用X18
{%endwarning%}
{%wrong%}
AAPCS64规定通过SP访问内存以及进入公共函数接口时，SP必须保持16字节对齐
{%endwrong%}
```arm-gas
.arch armv8-a

.text
.balign 4

.global _start
.type _start, %function

; 调用者——主程序
_start:
    ; 假设SP已经初始化并保持16字节对齐

    ; 准备参数：前8个64位整数参数通过X0-X7传递
    MOV     X0, #1
    MOV     X1, #2
    MOV     X2, #3
    MOV     X3, #4
    MOV     X4, #5
    MOV     X5, #6
    MOV     X6, #7
    MOV     X7, #8

    ; 为第9个参数分配16字节
    ; 其中8字节保存参数，另外8字节作为对齐填充
    SUB     SP, SP, #16
    MOV     X9, #9
    STR     X9, [SP, #0]

    ; 调用calculate
    ; 此处是公共函数调用边界，SP保持16字节对齐
    BL      calculate

    ; 清理栈参数区，此时X0中保存返回值
    ADD     SP, SP, #16

end_loop:
    B       end_loop

.size _start, .-_start


.global calculate
.type calculate, %function

; 被调用者
;
; int64_t calculate(
;     int64_t a, int64_t b, int64_t c,
;     int64_t d, int64_t e, int64_t f,
;     int64_t g, int64_t h, int64_t i);
;
; 参数：
;   X0-X7    = a-h
;   入口[SP] = i
;
; 计算：
;   result = (a+b)*(c+d)+e+f+g+h+i
;
; 返回值：
;   X0 = result

calculate:
    ; 建立48字节栈帧并保持16字节对齐
    ; 保存帧指针X29和链接寄存器X30
    STP     X29, X30, [SP, #-48]!
    MOV     X29, SP

    ; 保存即将使用的被调用者保存寄存器
    STP     X19, X20, [SP, #16]
    STR     X21, [SP, #32]
    ; [SP,#40]作为对齐填充

    ; 函数入口处的SP等于当前X29+48
    ; 因此第9个参数位于[X29,#48]
    LDR     X21, [X29, #48]

    ; 计算(a+b)*(c+d)
    ADD     X19, X0, X1
    ADD     X20, X2, X3
    MUL     X19, X19, X20

    ; 加上e、f、g、h、i
    ADD     X19, X19, X4
    ADD     X19, X19, X5
    ADD     X19, X19, X6
    ADD     X19, X19, X7
    ADD     X0, X19, X21

    ; 恢复被调用者保存寄存器
    LDR     X21, [SP, #32]
    LDP     X19, X20, [SP, #16]

    ; 恢复帧指针、链接寄存器和栈指针
    LDP     X29, X30, [SP], #48

    ; 根据X30中的返回地址返回
    RET

.size calculate, .-calculate
```
