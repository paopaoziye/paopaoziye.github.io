C语言学习笔记（一）

1.编译流程

①引言

概述：编译就是将源代码如.c文件转换为计算机能够识别并执行的机器指令，最终生成.exe和.out等可执行文件

完整的汇编过程通常可分为预处理、编译、汇编和链接四个阶段，这里以Ubuntu 22.04环境下的GCC工具链为例
如果不需要关注中间过程，可以直接使用gcc hello.c -o hello完成对以下脚本的整个编译流程，并生成可执行文件hello

编译完成后，直接在当前文件夹下运行./hello即可运行该可执行文件

在执行上述操作之前，需要确保系统安装了GCC及相关编译工具，在Ubuntu 22.04可以安装build-essential软件包
#include <stdio.h>

int main() {
    printf("Hello, World!\n");
    return 0;
}

②预处理

概述：预处理阶段对应的GCC命令为gcc -E hello.c -o hello.i，主要处理源文件中以#开头的预处理指令并生成预处理后的.i文件

预处理的核心工作为宏定义与展开、文件包含、条件编译和注释移除等，分别对应#define、#include、#if和#ifdef等指令
预处理阶段并不会进行完整的语法检查和类型检查，本质上是进行一些文本替换和清理工作
打开hello.i可以看到该文件被拓展到几百行，新增的代码主要是预处理器将stdio.h及其依赖无脑粘贴到对应位置
// 预处理前
#define PI 3.14159
#define MAX_BUFFER 1024

double area = PI * 2 * 2;
int buf[MAX_BUFFER];

// 预处理后
double area = 3.14159 * 2 * 2;
int buf[1024];

③编译

概述：编译阶段对应的GCC命令为gcc -S hello.i -o hello.s，主要是将C语言代码转化为对应架构的汇编代码，并进行一定的优化

编译阶段的核心工作包括词法分析、语法分析、语义分析、中间代码生成与代码优化，最终生成对应目标架构的汇编代码

比如说非法字符、缺少分号、类型不匹配、未声明变量和未使用变量等错误都是出现在编译阶段

编译器通常会对代码进行常量折叠、死代码消除、函数内联等优化，可以通过-O0、-O1、-O2、-O3等选项控制优化等级

-O0：关闭大多数性能优化，仅完成代码生成所必需的转换，尽量保持源码结构便于调试

-O1：启用较基础的优化，如常量传播、死代码删除、简单表达式化简和部分寄存器分配优化，在较低开销下提升性能

-O2：在-O1基础上启用更多全局和循环优化，如公共子表达式消除、更多代码移动、分支优化和更积极的数据流分析

-O3：在-O2基础上进一步采用更激进的性能优化，如更积极的函数内联、循环展开、循环向量化和自动SIMD优化

若编译器判断某个变量在代码执行阶段不会被修改，则会将其存入寄存器中提升访问速度，但不一定是合理的
编译器只会考虑软件逻辑，所以当一个变量会被硬件、中断或者其他线程修改时进行上述优化会出现逻辑错误
/* 常量折叠：将能提前计算好的值计算好 */
// 优化前
int seconds_per_day = 60 * 60 * 24;
int a = 10;
int b = a + 5;
// 优化后
int seconds_per_day = 86400; // 直接算出结果
int b = 15;                  // 变量 a 被传播并替换
/* 函数内联：因为函数调用是有开销的，所以对于短小且频繁调用的函数，编译器会直接展开 */
// 优化前
inline int square(int x) { return x * x; }
int main() {
    int res = square(5);
}
// 优化后
int main() {
    int res = 25; // 先内联变成了 5 * 5，再被常量折叠为 25
}
/* 寄存器优化：将不会被代码改变的变量存入寄存器中 */
// 优化前
uint32_t *status_reg = (uint32_t *)0x40021000;
while (*status_reg == 0) {
    // 死循环，等待硬件将寄存器的值置为 1
}
//优化后
uint32_t temp = *status_reg; // 只去内存读一次，随后把值存到CPU内部寄存器中
while (temp) {
    // 无限死循环，再也不会去读取 0x40021000 这个内存地址了！
}

④汇编

概述：汇编阶段对应的的GCC命令为gcc -c hello.c -o hello.o，主要是将汇编代码转化为机器语言，并生成目标文件.o

汇编器生成的目标文件在Linux中通常采用ELF格式，其中包含.text、.data、.rodata和.bss等不同的节
可以使用objdump -d hello.o对目标文件中的机器指令进行反汇编，结果通常依次显示指令地址、机器码和对应的汇编指令
目标文件中的指令地址通常为相对地址，而暂时无法确定的地址会保留占位值并记录重定位信息，等待链接阶段统一解析和修正
每个.c文件通常是独立编译的，汇编阶段只能确定当前文件内部函数和变量的位置，外部符号仍需在链接阶段解析

⑤链接

概述：链接阶段对应的GCC命令为gcc hello.o -o hello，主要是将目标文件和所需的库文件组合拼装为一个完整的可执行文件

目标文件中包含符号表，记录当前文件定义或引用的函数、全局变量等符号，以及这些符号的类型、位置和链接属性

对于需要跨文件链接的符号，可以分为强符号和弱符号，用于描述符号的链接可见性，以及出现同名符号时的解析规则

普通函数和全局变量通常产生强符号，弱符号通常需要借助GCC的__attribute__((weak))等编译器扩展显式声明

链接阶段的核心工作主要包括符号解析和重定位，前者负责找到每个外部符号对应的定义，后者负责确定代码和数据的地址布局

符号解析：将各个.o文件中对函数和全局变量的引用，与其他目标文件或库中对应的符号定义建立关联

重定位：将多个.o文件中相同的段合并随后为所有的符号分配绝对地址，最后根据重定位信息填补占位符

链接器通常不允许出现多个同名的强符号定义，如果一个强符号与多个弱符号同名，则会优先选择强符号
如果存在多个同名的弱符号定义，链接器通常会选择其中一个，但具体结果可能受链接顺序和工具链影响，容易导致隐蔽bug
/* ------ main.c ------ */
int x = 10; // 强符号：初始化的全局变量
void foo();

int main() {
    foo();
    return 0;
}

/* ------ utils.c ------ */
int x;      // 弱符号：未初始化的全局变量（名字和 main.c 里的 x 冲突）
            // 链接器会默默将此处的 x 映射到 main.c 里的 x 的地址！

void foo() { // 强符号
    x = 20;  // 表面上改的是 utils.c 的 x，实际把 main.c 的 x 给改了！
}

⑥程序内存布局

概述：一个典型的用户态进程内存布局如下图所示，主要由.text、.rodata、.data、.bss、heap和stack组成

程序运行后，不同类型的代码和数据通常会被组织到不同的内存区域，不同区域具有不同的用途、访问权限、生命周期和管理方式
这种分区方式便于操作系统对代码和数据进行独立的加载、保护、分配与回收，提高内存管理效率并增强程序运行时的安全性
该布局只是现代操作系统中常见的典型模型，实际地址分布会受到操作系统、处理器架构、编译器、链接方式和ASLR等因素影响
